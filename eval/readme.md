# Ctrl-World: Comprehensive World Model Evaluation

## 1. Overview

This directory contains a modular evaluation framework for assessing the quality and reliability of videos generated by the Ctrl-World world model.

The objective is to evaluate whether Ctrl-World successfully models the environment and predicts physically plausible future observations conditioned on robot actions.

A world model should do more than generate visually realistic videos. It should preserve object identities, understand object motion, represent interactions, and predict the consequences of actions in a physically coherent manner.

Therefore, this framework evaluates generated rollouts across seven dimensions:

1. Visual fidelity.
2. Temporal and motion consistency.
3. Object permanence and hallucination.
4. Object trajectory consistency.
5. Action-conditioned physical consistency.
6. Physical-rule violations.
7. Video distribution and realism.

The evaluation uses previously generated prediction and ground-truth rollout data. It does not execute the Ctrl-World model, generate new rollouts, or evaluate robot-policy success.

---

## 2. Evaluation Framework

| Evaluation dimension | What it evaluates |
|---|---|
| Visual fidelity | Whether generated observations visually match the recorded environment |
| Temporal consistency | Whether changes between consecutive frames are coherent |
| Object permanence | Whether objects consistently exist and retain their identities |
| Object trajectory consistency | Whether objects move smoothly without unexpected jumps or drift |
| Action-conditioned consistency | Whether predicted object changes correspond to the applied robot actions |
| Physical plausibility | Whether object interactions and spatial relationships obey basic physical constraints |
| Video realism | Whether generated video distributions resemble real video distributions |

The central distinction is between visual similarity and world consistency.

Visual similarity measures whether a generated frame resembles its reference. World consistency measures whether the generated environment behaves coherently over time and in response to actions.

## 4. Input Data

The evaluation framework uses paired prediction and ground-truth NPZ files generated by the existing Ctrl-World rollout pipeline.

Expected directory structure:

```text
synthetic_traj/
└── <task_name>/
    └── evaluation_data/
        └── trajectory_<DROID_ID>/
            ├── interaction_0_start_<frame>.npz
            ├── interaction_1_start_<frame>.npz
            └── ...
```

The existing rollout files contain fields including:

- `ground_truth`: Ground-truth video observations.
- `prediction`: Predicted video observations.
- `trajectory_id`: Trajectory identifier.
- `interaction_index`: Interaction segment identifier.
- `start_frame_index`: Starting frame of the interaction.
- `instruction`: Associated instruction.
- `fps`: Video frame rate.
- `frame_indices`: Corresponding frame indices.

The loader must inspect and preserve the actual array dimensions, camera ordering, frame ordering, image format, and metadata.

### Additional information for physical evaluation

Action-conditioned and physical evaluation may require:

- Robot end-effector positions.
- Robot actions or action commands.
- Object positions and bounding boxes.
- Object identities.
- Object masks or segmentation.
- Contact information, when available.

These must be obtained from existing trajectory metadata or extracted from video observations.

The implementation must distinguish recorded information from automatically estimated information.

Missing information must be reported explicitly. It must not be fabricated.

## 5. Evaluation Metrics

### 5.1 Visual Fidelity

These metrics measure similarity between predicted and ground-truth observations.

| Metric | Description | Better result |
|---|---|---|
| MSE | Mean Squared Error between corresponding pixels | Lower |
| PSNR | Peak Signal-to-Noise Ratio | Higher |
| SSIM | Structural Similarity Index | Higher |
| LPIPS | Learned Perceptual Image Patch Similarity | Lower |

These metrics establish the visual reconstruction quality of the generated observations.

### 5.2 Temporal and Motion Consistency

These metrics evaluate how the generated environment changes over time.

| Metric | Description | Better result |
|---|---|---|
| Temporal Difference Error | Difference between predicted and actual frame-to-frame changes | Lower |
| Optical Flow Difference | Difference between estimated motion in predicted and ground-truth videos | Lower |

Optical-flow comparison must be distinguished from true endpoint error against annotated ground-truth optical flow.

### 5.3 Object Permanence and Hallucination

A functioning world model should preserve objects and their identities across predicted frames.

This evaluation detects:

- Objects unexpectedly appearing.
- Existing objects disappearing.
- Object identity switching.
- Unexpected object duplication.
- Inconsistent object visibility.

The proposed metrics are:

| Metric | Description | Better result |
|---|---|---|
| Object Hallucination Rate (OHR) | Rate of unexpected object appearances or disappearances | Lower |
| Object Persistence Score | Consistency of object existence and identity across frames | Higher |
| Identity Switch Count | Number of object identity changes during tracking | Lower |
| Hallucination Severity Score (HSS) | Severity of detected object hallucination events | Lower |

Object detections and identities should be obtained using a consistent detector and tracker on both predicted and ground-truth videos.

Visibility and occlusion must be handled carefully. An object temporarily hidden behind another object should not automatically be classified as hallucinated or missing.

### 5.4 Object Trajectory Consistency

This evaluates whether objects move coherently over time.

The objective is to identify:

- Sudden object position jumps.
- Unnatural movement.
- Position drift.
- Inconsistent object trajectories.
- Unexpected changes in object motion.

Proposed metrics:

| Metric | Description | Better result |
|---|---|---|
| Position Anomaly Rate (PAR) | Frequency of abnormal object position changes | Lower |
| Trajectory Error | Difference between predicted and ground-truth object trajectories | Lower |
| Temporal Consistency Score (TCS) | Consistency of tracked object positions across frames | Higher |

Object trajectories can be extracted from bounding-box centers or segmentation-mask centroids.

For each object, compare the predicted and ground-truth trajectories using aligned frame indices.

Position-based measurements should account for image resolution and camera viewpoint.

### 5.5 Action-Conditioned Physical Consistency

This is one of the most important evaluations for Ctrl-World.

The objective is to determine whether the generated world responds coherently to the actions applied to it.

Examples:

- When the robot pushes an object, does the object move?
- When the robot grasps an object, does the object follow the gripper?
- When the robot releases an object, does it remain near the release position?
- Does an object move before the robot makes contact?
- Does the predicted object displacement correspond to the recorded displacement?

Proposed measurements:

| Metric | Description | Better result |
|---|---|---|
| Action-Conditioned State Error | Difference between predicted and ground-truth object state changes following an action | Lower |
| Displacement Error | Difference between predicted and actual object displacement | Lower |
| Action-Effect Consistency | Agreement between applied actions and observed object responses | Higher |
| Contact Timing Error | Difference between predicted and recorded contact timing | Lower |

These metrics require action information and object-state estimates aligned with the predicted and ground-truth frames.

Where action metadata is available, use the recorded actions associated with each interaction.

Do not infer successful grasping or contact solely from visual appearance when the evidence is insufficient.

### 5.6 Physical-Rule Violations

This evaluation examines whether the generated environment obeys basic spatial and physical constraints.

Detect the following:

| Violation | Description |
|---|---|
| Object penetration | Objects visually passing through other objects or surfaces |
| Floating objects | Objects remaining unsupported above a surface |
| Unnatural collision | Unexpected object overlap or collision behavior |
| Contact inconsistency | Object movement inconsistent with apparent contact |
| Unnatural motion | Sudden or physically implausible object displacement |
| Spatial instability | Objects changing their relative positions unexpectedly |

Proposed metrics:

- Physical Violation Rate.
- Object Penetration Rate.
- Floating Object Rate.
- Contact Consistency Score.
- Spatial Relationship Consistency.

These are visual or geometric diagnostics, not proof of full physical simulation correctness.

Where depth, camera calibration, or 3D geometry is unavailable, violations must be reported as image-space estimates rather than definitive 3D physical violations.

### 5.7 Video Distribution and Realism

**Fréchet Video Distance (FVD)**

FVD measures the difference between distributions of real and generated video clips using video feature representations.

It complements reference-based metrics by evaluating video-level distributional similarity.

Requirements:

- Calculate over collections of video clips.
- Use a suitable pretrained video feature extractor.
- Keep clip preprocessing consistent.
- Report sample counts.
- Do not interpret FVD as an individual frame reconstruction metric.
- Do not silently download pretrained weights.

## 6. Multi-Camera Evaluation

All applicable visual and object-level metrics should be calculated independently for each camera.

The framework should report:

- Per-camera PSNR, SSIM, and LPIPS.
- Per-camera temporal and optical-flow metrics.
- Per-camera object detection and persistence results.
- Per-camera trajectory consistency.
- Per-camera physical violation estimates.

Do not directly compare raw pixels between different camera views without established geometric correspondence.

If camera calibration or synchronized multi-view geometry is available, it can support additional cross-view consistency analysis.

---

## 7. Prediction-Horizon Analysis

Evaluate how world-model quality changes as the predicted future extends further in time.

For each applicable metric, analyze:

- Visual fidelity degradation.
- Object disappearance or hallucination over time.
- Object trajectory drift.
- Temporal instability.
- Increasing physical violations.
- Action-effect prediction errors.

Generate metric-versus-prediction-horizon plots.

This is important because a model may generate plausible short-term frames but fail to maintain a coherent world over longer predictions.

---

## 8. Aggregation and Reporting

Report results at:

| Level | Description |
|---|---|
| Frame-level | Metric values for individual frames |
| Object-level | Metrics for individual tracked objects |
| Interaction-level | Results for each interaction segment |
| Trajectory-level | Results for each trajectory |
| Camera-level | Results for each camera |
| Horizon-level | Results at different prediction horizons |
| Dataset-level | Overall evaluation results |

For applicable metrics, report:

- Mean.
- Median.
- Standard deviation.
- Valid sample count.

Also report the number of invalid or unobservable samples.

Object-level results must preserve object and trajectory identifiers wherever possible.

Avoid double-counting overlapping frames between interactions.

FVD must be reported at the video-collection level.

### `metrics/multiview_metrics.py`

- Compute camera-wise results.
- Preserve camera identifiers.
- Aggregate camera-level metrics.
- Support cross-view analysis only where valid geometric correspondence is available.

### `aggregation.py`

- Frame-level aggregation.
- Object-level aggregation.

### `visualization.py`

- Generate metric plots.
- Create frame comparisons.
- Create side-by-side videos.

### `utils.py`

Contains shared helpers for:
- Configuration.
- Logging.
- Directory creation.
- File handling.
- JSON serialization.
- Common utilities.

### `run_evaluation.py`

Coordinates the entire evaluation pipeline:

1. Parse command-line arguments.

3. Validate data.
4. Extract available object and action information.
5. Compute selected metrics.
6. Aggregate results.
7. Generate plots and visual comparisons.
8. Save CSV and JSON reports.
9. Print an evaluation summary.

The script must never initialize or execute the Ctrl-World model.

## 11. Implementation and Efficiency Requirements

The objective is to obtain meaningful world-model diagnostics without making evaluation unnecessarily slow.

Follow these principles:

- Reuse object detections and tracking results across all object-level metrics.
- Process sampled frames for expensive detection and tracking where appropriate.
- Use lightweight detection and tracking models where suitable.
- Avoid running large VLMs on every frame.
- Use image-space measurements when full 3D geometry is unavailable.
- Cache intermediate object tracks and extracted features within an evaluation run.
- Allow metrics to be enabled or disabled individually.
- Clearly report unavailable metrics when their required inputs are missing.
- Do not silently substitute a different metric.
- Keep all evaluation independent of model inference.

The evaluation should prioritize reliable and interpretable measurements over an unnecessarily large collection of expensive models.

## 12. Running Evaluation

Example command:

```bash
python -m eval.scripts.run_evaluation \
    --input_dir synthetic_traj/<task_name>/evaluation_data \
    --output_dir eval/results \
    --metrics all \
    --device cuda \
    --save_visualizations
```

Supported arguments should include:

| Argument | Purpose |
|---|---|
| `--input_dir` | Directory containing evaluation NPZ files |
| `--output_dir` | Evaluation results directory |
| `--metrics` | Selected metrics or all metrics |
| `--device` | CPU or CUDA where supported |
| `--batch_size` | Batch size for supported computations |
| `--save_visualizations` | Enable or disable visual outputs |

The exact command must match the implemented CLI.

## 14. Results and Interpretation

The final evaluation should answer the following questions:

1. Does the generated video visually resemble the recorded environment?
2. Do objects remain consistent across predicted frames?
3. Are object positions and trajectories coherent?
4. Does the environment respond appropriately to recorded robot actions?
5. Are object interactions physically plausible?
6. Does the world remain spatially consistent over time?
7. Does prediction quality degrade over longer horizons?
8. Are there differences in quality across camera views?

A high visual similarity score alone does not establish that the world model has learned physical dynamics.

Similarly, object tracking and image-space physical checks are proxies for world consistency, not complete 3D physics verification.

Results should be interpreted jointly across visual, object-level, temporal, action-conditioned, and physical metrics.

The framework evaluates the generated world and its predicted behavior, not robot-policy success.

## 15. Reproducibility

For every evaluation run, record:

- Input directory.
- Evaluation timestamp.
- Metric configuration.
- Detector and tracker models.
- Feature extractor configuration.
- Device and batch size.
- Sampling interval.
- Preprocessing settings.
- Number of valid and invalid samples.
- Metric-specific sample counts.
- Missing metadata and unavailable metrics.

Save these details in `config.json` and `summary.json`.

The evaluation should be reproducible using the same input rollouts, configuration, and model weights.
