# Ctrl-World Evaluation

This directory contains the evaluation framework for assessing the video predictions generated by the **Ctrl-World world model**.

The objective is to evaluate the quality of generated videos by comparing model predictions against their corresponding ground-truth videos. The framework is designed to be modular so that evaluation metrics and analysis methods can be added, modified, or extended independently.

The evaluation framework operates on the prediction data already generated by the Ctrl-World rollout scripts. It does not perform new rollouts or evaluate robot policy performance.

## 2. Scripts

The scripts are divided according to their responsibilities to keep the evaluation pipeline maintainable.

### 2.1 Main Execution and Data Handling

| File | Description |
|---|---|
| `run_evaluation.py` | Main entry point for executing the complete evaluation pipeline. Coordinates data loading, validation, metric computation, aggregation, and visualization. |
| `data_loader.py` | Locates and loads the generated `.npz` files containing ground-truth and predicted video frames. Extracts associated metadata such as trajectory ID, interaction index, camera information, and frame indices. |
| `validate_data.py` | Validates the loaded data before evaluation. Checks array shapes, frame counts, image dimensions, data types, and prediction-reference compatibility. |

### 2.2 Metrics

The `metrics/` directory contains independent implementations of the evaluation metrics.

| File | Description |
|---|---|
| `pixel_metrics.py` | Implements pixel-level metrics such as Mean Squared Error (MSE) and Peak Signal-to-Noise Ratio (PSNR). |
| `perceptual_metrics.py` | Implements perceptual and structural similarity metrics such as SSIM and LPIPS. |
| `temporal_metrics.py` | Evaluates temporal consistency by comparing changes and motion across consecutive generated and ground-truth frames. |
| `multiview_metrics.py` | Organizes and evaluates results across the different camera views. Initially, metrics will be reported independently for each camera. |

Each metric module will accept prediction and ground-truth data and return numerical evaluation results. Metric implementations will remain independent of data loading, result aggregation, and visualization.

### 2.3 Result Processing and Visualization

| File | Description |
|---|---|
| `aggregation.py` | Aggregates frame-level metric scores into interaction-level, trajectory-level, camera-level, and overall results. |
| `visualization.py` | Generates plots, frame comparisons, and side-by-side videos to help inspect prediction quality and identify visual artifacts. |
| `utils.py` | Contains shared helper functions used across the evaluation scripts, such as directory creation, metric formatting, and common processing operations. |

## 3. Results Directory

Every evaluation run will create a separate output directory under `results/`.

The directory will use a timestamp-based run ID to prevent previous results from being overwritten.

```text
│       └── frame_comparisons/
│
└── 20261126_110000/
    └── ...
```

### Result Files

| File / Directory | Description |
|---|---|
| `config.json` | Stores evaluation configuration, selected metrics, input paths, checkpoint information when available, and run metadata. |
| `summary.json` | Stores overall evaluation results, including mean, median, standard deviation, and evaluation counts. |
| `metrics_per_interaction.csv` | Contains metric scores for individual rollout interactions. |
| `metrics_per_trajectory.csv` | Contains aggregated metric scores for each trajectory. |
| `metrics_per_camera.csv` | Contains metric scores reported separately for each camera view. |
| `plots/` | Stores graphs and plots generated from the evaluation results. |
| `visualizations/` | Stores visual comparisons between generated predictions and ground-truth videos. |

**Note:** Original prediction `.npz` files and generated rollout videos will remain in their existing locations under `synthetic_traj/`. They will not be duplicated inside the evaluation results directory.

## 4. Evaluation Workflow

The evaluation pipeline follows these stages:

```text
Existing Ctrl-World Rollouts
          |
          v
   Data Loading
   (data_loader.py)
          |
          v
   Data Validation
   (validate_data.py)
          |
          v
   Metric Computation
   (metrics/)
          |
          v
   Result Aggregation
   (aggregation.py)
          |
          v
   Visualization
   (visualization.py)
          |
          v
   Evaluation Results
   (results/<run_id>/)
```

### Stage 1: Data Loading

The pipeline reads the paired prediction and ground-truth arrays from the `.npz` files generated by the rollout scripts.

### Stage 2: Data Validation

The loaded data is checked to ensure that predictions and ground-truth frames are compatible and correctly aligned.

### Stage 3: Metric Computation

The selected evaluation metrics are independently calculated for the generated predictions and their corresponding references.

### Stage 4: Result Aggregation

Individual frame scores are aggregated at different levels:

- Frame level
- Interaction level
- Trajectory level
- Camera level
- Overall evaluation level

Where applicable, results will also be grouped by prediction horizon to examine how prediction quality changes over time.

### Stage 5: Visualization and Reporting

The evaluation outputs are saved as structured CSV and JSON files, along with plots and visual comparisons.

## 5. Planned Evaluation Metrics

The following metrics are planned for the initial evaluation framework.

| Category | Metrics | Purpose |
|---|---|---|
| Pixel-level fidelity | MSE, PSNR | Measures pixel-wise differences between generated and reference frames. |
| Structural similarity | SSIM | Measures structural similarity between generated and reference images. |
| Perceptual similarity | LPIPS | Measures perceptual differences using deep visual features. |
| Temporal consistency | Frame-difference error | Compares temporal changes between consecutive generated and reference frames. |
| Motion consistency | Optical-flow-based comparison | Examines differences in estimated motion between generated and reference videos. |
| Multi-view analysis | Per-camera metric breakdown | Examines prediction quality independently across camera views. |

Additional video-level metrics, such as Fréchet Video Distance (FVD), may be considered in later stages.

The metrics will be introduced incrementally. The initial implementation will focus on pixel-level and perceptual evaluation before extending the framework to temporal and motion-based analysis.

## 6. Evaluation Design Principles

The evaluation framework follows these principles:

1. **Modularity:** Each metric and processing stage is implemented independently.
2. **Reproducibility:** Every evaluation run stores its configuration and results.
3. **Separation of responsibilities:** Data loading, validation, metric computation, aggregation, and visualization are handled by separate modules.
4. **Multi-level analysis:** Results are reported at frame, interaction, trajectory, camera, and overall levels where applicable.
5. **Extensibility:** New metrics and analysis methods can be added without modifying the complete pipeline.
6. **Reference-based evaluation:** Generated predictions are compared with their corresponding ground-truth frames.

### Important Evaluation Consideration

Reference-based metrics measure similarity to the recorded ground-truth future. They do not necessarily capture every physically plausible future outcome. Therefore, numerical metrics should be interpreted alongside visual comparisons and the temporal behavior of generated videos.

## 7. Implementation Plan

The evaluation framework will be implemented incrementally in the following order:

| Step | File | Implementation Goal |
|---|---|---|
| 1 | `data_loader.py` | Load and organize prediction and ground-truth data. |
| 2 | `validate_data.py` | Validate data structure, dimensions, and alignment. |
| 3 | `pixel_metrics.py` | Implement MSE and PSNR. |
| 4 | `perceptual_metrics.py` | Implement SSIM and LPIPS. |
| 5 | `aggregation.py` | Aggregate metric results at different levels. |
| 6 | `visualization.py` | Generate plots and visual comparisons. |
| 7 | `temporal_metrics.py` | Implement temporal consistency evaluation. |
| 8 | `multiview_metrics.py` | Implement multi-camera result analysis. |
| 9 | `run_evaluation.py` | Integrate all modules into a single evaluation pipeline. |

The first implementation milestone is to establish reliable data loading and validation. Metric implementation will begin only after the input data has been verified.

---

## 8. Scope

This evaluation directory is dedicated to assessing the generated video predictions of the Ctrl-World world model.

The scope includes:

- Visual fidelity of generated frames.
- Perceptual similarity to reference frames.
- Temporal consistency of generated videos.
- Motion consistency.
- Prediction quality across different camera views.
- Quantitative results and qualitative visual analysis.

Robot policy performance and policy success evaluation are outside the scope of this evaluation framework.
